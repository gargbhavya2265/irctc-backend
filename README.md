🚆 Railway Booking Platform – Event-Driven Microservices Architecture

A full-stack railway booking platform built using a microservices architecture. The project demonstrates service decomposition, synchronous and asynchronous communication, distributed booking workflows, search indexing, caching, payment processing, and containerized infrastructure.

This project is built for learning and demonstrating backend architecture concepts commonly used in scalable distributed systems.

🔄 Event-Driven Communication

Apache Kafka is used for asynchronous communication between services.

Example administrative workflow

Admin Service
      │
      │ Station / Train / Schedule Events
      ▼
Apache Kafka
      │
      ├──────────────► Search Service
      │
      └──────────────► Inventory Service

Example booking workflow

Booking Service
      │
      ▼
Inventory Service ───► Seat Reservation / Lock
      │
      ▼
Payment Service
      │
      ▼
Kafka Events
      │
      ├──────────────► Booking Service
      │
      └──────────────► Notification Service

This architecture allows services to communicate asynchronously and reduces tight coupling between independent business domains.

🚀 Getting Started

Prerequisites

Make sure the following are installed:

Node.js

npm

Docker

Docker Compose

Git

Clone the Repository

git clone <your-repository-url>
cd irctc-backend

Start Infrastructure

Start the required infrastructure services:

docker compose up -d

Verify running containers:

docker ps

Depending on your Docker configuration, the infrastructure may include services such as:

PostgreSQL

Redis

Kafka

Zookeeper

Elasticsearch

Supporting management tools

Configure Environment Variables

Each service contains an .env.example file.

Create a local .env file for each service.

Linux / macOS

cp .env.example .env

Windows PowerShell

Copy-Item .env.example .env

Update the environment variables according to your local setup.

Never commit .env files containing secrets, API keys, or credentials.

Install Dependencies

Install dependencies for each service.

Example:

cd user-service
npm install

Repeat the process for:

api-gateway

admin-service

booking-service

payment-service

inventory-service

search-service

notification-service

frontend

Database Setup

Services using Prisma require their database configuration to be available through environment variables.

Run the appropriate Prisma commands inside each Prisma-based service:

npx prisma generate

Apply migrations when required:

npx prisma migrate dev

▶️ Running the Application

Start the infrastructure first:

docker compose up -d

Then start backend services in separate terminals.

Example:

cd admin-service
npm run dev

Similarly start:

user-service

inventory-service

search-service

payment-service

booking-service

notification-service

api-gateway

Finally start the frontend:

cd frontend
npm run dev

The frontend development server will display the local URL in the terminal.

🔐 Security Notes

.env files should be excluded from version control.

Secrets and credentials should never be committed to the repository.

JWT secrets should be configured through environment variables.

Internal service communication should use appropriate authentication or protected credentials.

Payment credentials should only be stored in environment variables.

Production deployments should use secure secret-management practices.
